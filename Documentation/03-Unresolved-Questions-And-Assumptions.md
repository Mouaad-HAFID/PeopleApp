## Proposals, Not Established Requirements

- Use the accepted four-field set and user-selectable AND/OR combination. D005 accepts exact UserName/typed Gender equality and case-sensitive contains matching for FirstName/LastName; raw expressions and nested groups are not approved by D006.
- D020 supersedes D007's six-field set with five editable fields including mutable UserName. Gender is explicitly read-only; no workaround is assumed.
- Use a fresh session per application run and retain that root throughout the run. D001 rules out adding saved-session machinery solely for cross-restart retention; the precise startup interaction can wait until implementation.
- D017/D018 accept xUnit v3, a small HTTP boundary, controlled-response tests, built-in HTTP/JSON, and two projects. A generated OData client, mocking library, additional class libraries, or generic host is not selected; add one only for an established need rather than hypothetical extensibility.
- D011/D012 require application-behavior and read-only live availability checks in the default suite. Live update acceptance remains separate; no automated mutation suite is approved. D013/D014/D015's list/query-option and single-sort-field scope and D016's explicit clearing capability are accepted.

No proposal above should be silently promoted into the implementation contract.
